Your first Godot game · ages 12 & up

Make a character walk and jump — your first win in Godot

Godot can feel like a cockpit with a hundred buttons. It isn't, really — it's just four areas that never move. Learn those four, and the rest is easy. This guide gets you from "I opened Godot" to "my character jumps!" — one small click at a time.

4 words you'll keep hearing

That's it. Learn these four and you can follow any Godot tutorial.

Node

One single Lego brick. A picture is a node. A sound is a node. A shape is a node.

Think: a piece.

Scene

A bunch of nodes clicked together into one thing — like your whole Player.

Think: a finished build made of pieces.

Inspector

The settings panel. Click a node, change its numbers and pictures here.

Think: the knobs.

Script

A page of instructions that tells a node how to act — like "jump when I press space."

Think: the brain.
PART 1

Your first win — walk & jump

Do these in order. Tick each box when you finish it. By the end, a character you made will run and jump when you press the keys. That's a real game moment. 🎉

1
Top bar

Open Godot — from scratch, or the camp's project

Open the Godot app first. A list of projects appears. Pick your path:

  1. Starting from scratch: click + New Project (top-right), name it Reef Runner, pick a folder, click Create & Edit.
  2. The camp gave you a project folder: click Import, find that folder, open the project.godot file inside it, then Import & Edit.
  3. Either way, the big editor opens. Find your four colours from the map. You're home.
You'll know it worked: you see the editor with its 4 areas — an empty dark Stage in the middle (from scratch), or the camp's game already loaded.
2
Parts list

Make the character (a new Scene)

  1. In the Parts list (top-left), click + Other Node (or the big “Other Node” button).
  2. In the search box, type CharacterBody2D. Click it, then Create.
  3. It appears in the Parts list. Double-click its name and rename it Player.

Why this one? CharacterBody2D is Godot's special node for "a thing the player controls that bumps into walls and floors." It's the body your hero lives in.

You'll know it worked: Player is now at the top of the Parts list.
3
Parts list

Give her a picture and a body shape

A CharacterBody2D is invisible on its own. It needs two child pieces: something to see, and something to bump with.

  1. Right-click Player → Add Child Node → search Sprite2D → Create. (This is her picture.)
  2. Click the new Sprite2D. In the Inspector (right), find Texture → Load → pick any character image from your Files. (No image yet? Godot's built-in icon.svg works fine for now.)
  3. Right-click Player again → Add Child Node → search CollisionShape2D → Create. (This is her bump-shape.)
  4. Click CollisionShape2D. In the Inspector, click Shape → New RectangleShape2D. Drag its handles in the Stage until the box roughly covers her.
You'll know it worked: Player now has two pieces under it in the Parts list, and you see her picture in the Stage.
4
Top bar

Teach Godot the keys (Input Map)

The brain we add next will say things like "when move_right is pressed…". First we tell Godot what those names mean. Do this once.

  1. Top bar: Project → Project Settings → tab Input Map.
  2. In "Add New Action", type move_left → Add. Do the same for move_right and jump.
  3. Next to move_left, click the +, press the ← Left Arrow key, confirm. For move_right use →. For jump press Space.
  4. Click Close.

Spelling matters here. The names must be exactly move_left, move_right, jump — all lowercase, with the underscore. The code won't find them otherwise.

You'll know it worked: three actions are listed with a key icon next to each.
5
Parts list → Script

Give her a brain (the movement script)

  1. Right-click Player → Attach Script → Create. A code page opens.
  2. Delete what's there and type (or paste) the code below.
  3. Press Ctrl/⌘ + S to save.
Player.gd — the movement brainGDScript
extends CharacterBody2D

@export var speed: float = 250.0
@export var jump_force: float = -450.0
@export var gravity: float = 1200.0

@onready var visual = get_node_or_null("Sprite2D")

func _physics_process(delta):
    # Gravity pulls her back down.
    if not is_on_floor():
        velocity.y += gravity * delta

    # Move left and right.
    var direction = Input.get_axis("move_left", "move_right")
    if direction != 0:
        velocity.x = direction * speed
    else:
        velocity.x = move_toward(velocity.x, 0, speed)

    # Jump — only when standing on the ground.
    if Input.is_action_just_pressed("jump") and is_on_floor():
        velocity.y = jump_force

    # Face the way she's walking.
    if direction != 0 and visual:
        visual.flip_h = direction < 0

    move_and_slide()

In plain words: every tick, fall if not on the floor · slide left/right with the arrow keys · jump if Space is pressed and she's on the ground · flip the picture to face her direction · then do the move (move_and_slide).

You'll know it worked: a little scroll icon appears next to Player in the Parts list, and there are no red errors at the bottom.
6
Parts list

Give her ground to stand on

Right now she'd fall forever. Let's add a floor. We'll build it as its own little scene root so the Player has a world to live in.

  1. Click the + tab at the top of the Stage to make a new scene. Add a Node2D, rename it Level.
  2. Right-click Level → Add Child Node → StaticBody2D. Add a CollisionShape2D under it with a wide, flat RectangleShape2D — that's the floor.
  3. Add a Sprite2D (or ColorRect) so you can see the floor too.
  4. Drag your Player.tscn from the Files panel into the Level parts list. Move her up above the floor in the Stage.
You'll know it worked: in the Level scene you see the floor and the Player sitting above it.
7
Top bar · GO

Press GO and play! 🎉

  1. Press the big ▶ Play button (top-right) or F5.
  2. Godot asks for a main scene the first time — pick Level.
  3. Press the ← → arrows to walk. Press Space to jump.
🎉 YOU DID IT. You made a character move in a game you built. Everything else — coins, enemies, score — is just more of this same loop: add a piece, give it a brain, press GO.

Help! It's not working

This is the normal part of making games — not a sign you did it wrong. Find your problem, open it, fix it.

😵 She falls straight through the floor▶
The floor needs a CollisionShape2D with an actual shape, and the Player needs one too. If either shape is missing (or empty), they can't bump. Check both have a RectangleShape2D assigned in the Inspector.
🕹 She won't move at all▶
Your key names must match the code exactly: move_left, move_right, jump (lowercase, underscore). Re-open Project → Project Settings → Input Map and check the spelling. A capital letter or a space breaks it.
🚀 She flies up and never comes down▶
jump_force should be a negative number (like -450) — in Godot, up is negative. And gravity should be positive. Check them in the Inspector under the Player (they show up because we wrote @export).
🟥 Red text at the bottom of the screen▶
That's the Output/Errors strip talking. Read the first red line — it usually names the node it can't find. 90% of the time it's a spelling difference between the script and a node name (e.g. the script says Sprite2D but you named it something else).
⬛ Nothing happens when I press Play▶
Make sure you picked Level as the main scene. To change it later: Project → Project Settings → Application → Run → Main Scene.

@onready var fallback_visual = get_node_or_null("Sprite2D")

Day 3Coins, enemies, score & game-over▶

Handout videos: Add Restart Zones with Timers · Adding & Coding Coins · Adding Enemies & Raycasting · Make Enemy Deaths Look Better · Add Text Instructions through Labels · Add Sound Effects · Game Manager, Scoring & End Game.

A patrolling enemy is an Area2D that slides back and forth. When the Player touches it, the Game Manager takes a life:

Enemy.gd — moves left/right, hurts on touchGDScript
extends Area2D

@export var speed = 100
@export var move_distance = 200

var start_position
var direction = 1

func _ready():
    start_position = position

func _process(delta):
    position.x += speed * direction * delta
    if abs(position.x - start_position.x) > move_distance:
        direction *= -1   # turn around at the edge

func _on_body_entered(body):
    if body.name == "Player":
        get_node("/root/Level/GameManager").lose_life()

The Game Manager is the scorekeeper node. It holds the lives and reef count, and shows the HUD text:

GameManager.gd — lives, score, game overGDScript
extends Node

var lives = 4
var reefs_saved = 0
var game_over = false

@onready var lives_label = $"../HUD/LivesLabel"
@onready var reef_label = $"../HUD/ReefLabel"
@onready var game_over_label = $"../HUD/GameOverLabel"

func _ready():
    update_hud()
    game_over_label.visible = false

func save_reef():
    if game_over: return
    reefs_saved += 1
    update_hud()

func lose_life():
    if game_over: return
    lives -= 1
    update_hud()
    if lives <= 0:
        show_game_over()

func update_hud():
    lives_label.text = "Lives: " + str(lives)
    reef_label.text = "Reefs Saved: " + str(reefs_saved)

func show_game_over():
    game_over = true
    game_over_label.text = "Game Over\nYou saved " + str(reefs_saved) + " reefs!"
    game_over_label.visible = true

The HUD (the Lives/Reefs text on screen) is a CanvasLayer with Label nodes — it sits on top of the game and never scrolls away. Coins and reefs are Area2D pieces too: when the Player enters them, they call save_reef() and delete themselves.

Notes for you, the guide

You don't have to remember Godot — you have to remember the 4 colours and point at them. That's the whole job.

  • Teach the map first, code last. Spend the first 5 minutes just naming the 4 areas out loud together. Everything after lands easier.
  • One step on screen at a time. Do a step, let them do it, tick the box, then move on. The check-off boxes keep restless attention anchored.
  • Say the "why" in one line. "The CollisionShape is her bump-shape." Kids remember the picture, not the term.
  • Expect the fall-through-floor bug. It happens to everyone. Treat it as the fun puzzle, not a failure — use the "Help!" cards.
  • Celebrate the jump. The moment a character jumps is the hook. Stop and cheer it before adding anything else.
  • Pace it: Map + glossary ≈ 10 min · Steps 1–7 ≈ 35–45 min · that's one satisfying session. Save Part 2 for later days.
